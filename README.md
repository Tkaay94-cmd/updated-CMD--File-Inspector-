# ThirdParty Inspector

**ThirdParty Inspector 1.0.0-rc1** is an on-device Android review utility for surfacing potentially unusual application, accessibility, device-administration, and root-environment signals. It is designed to support investigation, not to make a malware determination or to modify the device.

The release-candidate dashboard presents a saved scan status, total risk score, severity breakdown, and the five most recent findings. Selecting **Scan now** runs the existing local scan pipeline and persists the resulting scan and findings in Room.

## What the release candidate does

The dashboard starts a foreground, in-app scan and reads only metadata available through public Android APIs. A scan may evaluate visible installed packages and their declared permissions, enabled accessibility services, active device-administration entries where Android exposes them, and conservative read-only root indicators. Findings are generated by transparent heuristic rules such as recently installed applications, combinations of accessibility and overlay capabilities, unusual installer metadata, sensitive permission combinations, device-admin roles, and root-management indicators.

Each completed scan is saved locally with its timestamp, device/Android version metadata, risk score, and individual findings. The dashboard automatically observes the latest saved scan and refreshes its summary when a new scan completes. Scan persistence is transactional: a dashboard scan does not expose a saved scan record without its associated findings.

The codebase uses **Kotlin, Jetpack Compose, Hilt, Room, and WorkManager**. The application has a **minimum SDK of 29** and targets/compiles against SDK 34.

## Important limitations

This application is intentionally conservative and does not provide complete device forensics.

- Android package-visibility protections can limit which installed packages are visible on Android 11 and later. The app does **not** declare `QUERY_ALL_PACKAGES`; therefore results may be incomplete by design.
- Permission findings are based on declared/requested permission metadata, not a proof that a permission is currently granted, used, malicious, or unnecessary.
- Accessibility and device-admin visibility varies by OEM, Android version, work profile, and policy. A missing entry is not proof that the capability is absent.
- Root checks only look for a small set of publicly observable, read-only indicators. An indicator is not conclusive proof of compromise, and no result is a guarantee that a device is unmodified.
- The in-app dashboard does not request storage access. The existing file inspector can scan only user-selected Storage Access Framework tree URIs supplied to the scan use case; a directory picker is not part of this release-candidate dashboard.
- No finding triggers removal, remediation, network reporting, or automatic background scanning. Review findings in context before changing device settings or uninstalling an app.

## Privacy and safety

ThirdParty Inspector is designed for local review.

- It declares **no dangerous runtime permissions** and does not declare `QUERY_ALL_PACKAGES`.
- It does not attempt to root a device, execute privileged commands, bypass Android sandboxing, or inspect another app's private data.
- It does not include analytics, telemetry, advertising SDKs, cloud scanning, or an export/upload workflow.
- Scan results are stored in the app's local Room database. Android Auto Backup is disabled (`android:allowBackup="false"`) so findings are not automatically included in device backup/restore flows.
- File inspection, when invoked by a future caller, is limited to SAF URIs explicitly granted by the user. The scanner only reads accessible content and does not alter files.

## Build and run

### Prerequisites

Install **JDK 17** and Android SDK Platform/Build Tools matching the values in `gradle.properties` (currently Android 34 and Build Tools 34.0.0). Android Studio is recommended for device/emulator deployment. A device or emulator must run Android 10 / API 29 or newer.

For command-line builds, set `ANDROID_HOME`/`ANDROID_SDK_ROOT`, or create a local, untracked `local.properties` file:

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

Then run:

```bash
./gradlew :app:assembleDebug
```

The debug APK is written under `app/build/outputs/apk/debug/`.

### Tests and static checks

Run the JVM unit suite:

```bash
./gradlew :app:testDebugUnitTest
```

Run Android lint:

```bash
./gradlew :app:lintDebug
```

Connected Compose/Hilt instrumentation tests require an available emulator or physical device:

```bash
./gradlew :app:connectedDebugAndroidTest
```

The primary GitHub Actions verification workflow runs the JVM tests and creates a debug APK. It has read-only repository permissions and uploads build/test outputs as workflow artifacts; it does **not** create a GitHub release.

## Architecture

| Layer | Responsibility |
|---|---|
| `ui/dashboard` | Compose dashboard, Hilt `DashboardViewModel`, UI state, and pure Room-to-dashboard mapper. |
| `domain/usecase/RunScanUseCase` | Runs the available inspectors, applies risk rules, calculates a score, and persists a scan. |
| `scanner` | Read-only public-API inspectors and pure rule logic for package, permission, accessibility, device-admin, root, and optional SAF file signals. |
| `data/local` | Room entities and DAO for scans/findings. |
| `data/repository` | Transactional scan persistence and observable result retrieval. |

## Release checklist

Before promoting this release candidate, complete the following checks on representative Android 10, 11, 13, and 14 devices/emulators where available:

- [ ] Run `:app:testDebugUnitTest`, `:app:lintDebug`, and `:app:assembleRelease` with JDK 17.
- [ ] Execute the connected Compose/Hilt test suite and manually confirm that **Scan now** disables while running, returns to an idle state, and displays the newly persisted scan.
- [ ] Validate behavior with no findings, several findings, Android-restricted package visibility, enabled accessibility services, and managed/work-profile devices.
- [ ] Review every heuristic finding and recommendation with security/product owners for false-positive wording and appropriate user guidance.
- [ ] Perform a privacy review of the final manifest and APK to confirm no dangerous permissions, `QUERY_ALL_PACKAGES`, telemetry, or unintended backup path were introduced.
- [ ] Configure and protect the production signing key outside the repository; verify the signed release artifact and version metadata (`1.0.0-rc1`).
- [ ] Decide and document a user-support/remediation path before any public distribution. The app currently only reports findings.

## Development notes

The risk score is a heuristic aggregation of finding severity and confidence. It is useful for prioritization only, is not normalized to a 0–100 scale, and must not be interpreted as a security guarantee. Contributions should preserve the current privacy posture: use public Android APIs, avoid speculative permissions, keep data on device unless an explicit user-approved export feature is designed and reviewed, and add tests for new pure rule or state-mapping logic.
